## VPS access (three independent paths)

1. `pisairtel-vps` — direct SSH on port 22 (key-only; UFW allows 22 to all — do NOT re-add per-IP allow rules: the admin IP is dynamic and whitelist rules caused the Oct-21 lockout)
2. `pisairtel-vps-ts` — SSH over Tailscale (100.103.180.105); works when port 22 is filtered since Tailscale tunnels outbound
3. `tailscale ssh root@100.103.180.105` — keyless Tailscale SSH; survives even sshd failure (served by tailscaled, not OpenSSH)
4. Out-of-band: provider noVNC console via the hosting panel

## Deployment (VPS)

- Production runs in Docker on the VPS (`pisairtel-vps` SSH alias, host 162.35.104.28).
- App container: `syspro-erp-app` (image `syspro-erp-app:patched`), DB: `syspro-erp-db` (postgres:17-alpine). Compose project dir: `/opt/syspro-erp`.
- `docker-compose.yml` and `Dockerfile` ARE tracked in this repo — keep them in sync; secrets live in `/opt/syspro-erp/.env` (untracked, see `.env.example`).
- Deploy: `scripts/deploy-vps.sh` (packages source, backs up server dir to `/root/syspro-erp-backup-*`, rsyncs, builds with `--build-arg DATABASE_URL`, tags `patched`, recreates, health-checks).
- The `next build` requires `DATABASE_URL` as a build arg — page-data collection queries the DB at build time.
- `syspro-erp-net` is declared `external` in compose because `pisairtel-nginx` is attached to it. NEVER let compose manage/remove it — `docker compose up` on a managed version tears the network down and strands nginx + db with empty network configs (happened 2026-10-21; fix: reconnect via `docker network connect` or recreate with the external declaration).
- Server-only dirs that must never be deleted by syncs: `/opt/shared-nginx/conf.d` (shared nginx vhosts), `/opt/syspro-erp/.env`, `/opt/pisairtel-sms/docker-compose.override.yml` (nginx mounts + external networks).

  `DATABASE_URL=postgresql://syspro:syspro_secure_pass_2026@localhost:5433/syspro_erp?sslmode=disable`
- Finance suites are skipped without `DATABASE_URL` set. Apply migrations through the same connection (`psql` is not installed on the host; run from a client or inside the container).

## Performance observability

- `pg_stat_statements` is enabled on the prod db (preloaded via `docker-compose.yml` command args). Baseline reset 2026-10-21.
- Ranking script: `db/scripts/pg-top-queries.sql` — run via docker exec (header comments in the file show the command) or through the SSH tunnel with `psql -f`.
- App-level slow query logging: set `SQL_SLOW_MS=500` in the app env (already set in prod `/opt/syspro-erp/.env`) — queries over the threshold log `[slow-query]` warnings.

## VPS cron jobs (installed on host crontab)

- `*/15` `/opt/syspro-erp/cron/run-automation.sh` — POSTs `/api/cron/automation` (CRON_SECRET from .env): drains automation queue, notification outbox, webhook deliveries, scheduled reports, dunning, SLA checks.
- `02:30` `/opt/syspro-erp/cron/backup-db.sh` — `pg_dump` → `/root/db-backups/syspro_erp-*.sql.gz`, 14-day retention. Backups are on the same VPS (no off-site copy yet).
- `*/5` `/opt/syspro-erp/cron/health-check.sh` — app/local + public-domain health, db health, pool liveness, disk; emails `admin@pisairtel.com` via `send-alert.py` (SMTP creds from `/opt/syspro-erp/.env`) on DOWN/RECOVERED transitions. State in `/var/lib/syspro-health`, logs in `/var/log/syspro-health.log`.
- Script sources are tracked in `scripts/ops/` — keep server copies in sync when editing.

## Conventions

- Canonical GL posting goes through `src/lib/finance/gl.ts` `postGLEntry` — never write journal_entries/journal_entry_lines directly.
- Tables are provisioned at runtime via idempotent `ensure*Tables` (`CREATE TABLE IF NOT EXISTS`, `ALTER ... ADD COLUMN IF NOT EXISTS`); migrations in `db/migrations/` mirror them and must stay idempotent.
- Postgres `date` columns come back as JS `Date` at local midnight — cast to `::text` in SQL before slicing, or WAT shifts the date back a day.
- `journal_entry_lines` has no `tenant_slug` — tenant filtering joins through `journal_entries`.
- Test data uses `__<prefix>_<ts>__` tenant slugs; clean them after runs.
- Employee portal expenses live in `expenses` (`type='reimbursement'`, `submitter_employee_id` links the employee); `admin_employee_expenses` is a read-only archive — the 20261128 migration copied rows over preserving ids.
- Approval config lives in `tenants.settings.approvals`: `expenseMinAmount`/`employeeExpenseMinAmount` (0 = always gate), `expenseDefaultChain`, `expenseStep2Amount`/`expenseStep3Amount` (defaults ₦50k/₦500k), `approvalSlaHours`/`approvalSlaAction` ('remind'|'escalate'). Per-rule SLA overrides via `approval_rules.conditions.slaHours/slaAction`; the automation cron sweeps via `escalateStaleApprovals()`.
- Approver delegation uses `approval_delegates` (delegator → delegate, optional entity_type + validity window); the engine records `delegatedFor` on decisions.
- Company officers (MD, Chairman, …) are tenant-configured posts in `settings.approvals.officers` = `[{title, userIds[]}]`. Rule steps use `role:<slug-of-title>`; they resolve to concrete userIds at initiation (company-wide, parallel approvers). `role:dept_manager` is department-scoped — everything else officer-named is company-wide. Built-in role placeholders stay symbolic on purpose: resolving them to tenant_admin ids would lock out employee-side role holders.
- Document approval gates (`src/lib/finance/approvals.ts`): entity types `bill`, `payment`, `payroll_run`, `employee_salary_change`, `credit_limit_change`, `stock_adjustment`, `bank_guarantee`, `invoice_discounting`, `pricing_change` all route through the same engine. Threshold keys in `settings.approvals`: `billMinAmount`, `paymentMinAmount`, `payrollMinAmount`, `stockAdjustmentMinAmount`, `bankGuaranteeMinAmount`, `invoiceDiscountingMinAmount` (salary/credit/pricing always gate). Gated docs sit at `pending_approval`; `applyApprovalOutcome` replays the deferred effect (GL posting, bill balances, salary/credit apply, stashed stock movement, treasury facility, pricing upsert). Staged fields: `admin_employees.pending_salary`, `finance_customers.pending_credit_limit`; `approval_id` links on bills/vendor_payments/admin_payroll_runs. Payroll approval uses shared `src/lib/hr/payroll-post.ts`; creator cannot self-approve (SoD).
- POS discounts: `settings.pos.discountCapPct` (or `settings.approvals.posDiscountCapPct`) caps line/order discounts; breaching sales need `discount.overrideBy` naming a manager/HOD/executive/officer — logged via `pos.discount_override` event.
- Gated actions (`src/lib/finance/gated-actions.ts`): declarative maker-checker registry. Flows register a def `{domain, mode, amount, describe, run, reverse?, staged?, rejected?, overLimit?}` and routes call `gateOrRun(tenant, name, payload, ctx)` → `{status:'pending'|'ran'|'denied'}`. Modes: `block` (defer to approval), `override` (real-time cap + `payload.overrideBy` authorized via `canOverride`), `review` (apply now, post-hoc approval row; rejection calls `reverse`). Registered: `vendor_bank_change`, `payroll_adjustment`, `imprest_advance`/`imprest_replenish`/`imprest_disburse`, `role_assignment`, `pos_cash_movement`, `pos_refund`.
- Delegation-of-authority matrix: `settings.approvals.authorityMatrix = { <domain>: [{upTo, approvers: (spec|spec[])[], mode?}] }` — domains: spend|treasury|people|inventory|master_data|system|sales. Specs: `dept_manager`, `officer:<title>`, `role:<key>`, `user:<id>`; a band's `approvers:[]` = auto-approve. When a band exists it owns gating+chain for that domain; rules still match first. `entityData.forceOfficerApproval` appends a company-officer step regardless of amount — vendor payments use it when `vendors.bank_details_changed_at` is <30d old (set by approved vendor_bank_change). Vendor bank edits stage in `vendors.pending_bank_details` until approved.
- Converged gated actions (also in the registry): `purchase_requisition` (row stays 'pending' + `approval_id`; gates via `requisitionMinAmount`/spend band; `runUngated:false` preserves the manual PATCH when unconfigured), `leave_request` (always gated, amount=days → people matrix can auto-approve short leave; `admin_leave.approval_id` links), `invoice_delete`/`period_close`/`employee_termination`/`employee_delete`/`asset_disposal` (always gated), `stock_transfer_completion` (gates on value ≥ `stockTransferMinAmount`; goods move only on approval via `lib/inventory/transfers.ts`), `budget_approval` (submission routes to chain; DRAFT→APPROVED on approve, →DRAFT on reject + budget_approvals audit row). Rule `conditions.action` scopes a gated_action rule to one registered action. Gated actions without departmentId default to `role:finance_manager` step 0 (dept_manager can't resolve).
- `budgets` has no `updated_at` column; `changeBudgetStatus` bumps `version_number` per transition (unique budget_versions key).
- `employee_bank_change` mirrors vendor_bank_change on the payroll side: staged `admin_employees.pending_bank_details`, `bank_details_changed_at` stamps on approval and escalates payroll runs covering that employee to a company officer for 30d. Vendor payments escalate on `vendor_bank_recently_changed`, `first_time_payee`, `payment_velocity` (3+ in 7d), `off_hours` (outside 07:00–19:00 WAT / weekends).
- `asset_value_adjustment` + `asset_capitalize` are always-gated (system domain); `coa_change` is opt-in (gates only via a master_data matrix band or an action-scoped rule).
- Approvals config self-modification: `setOfficers`/`setApprovalSettings` emit `approvals.config_changed` events. Policy tab (`/tenant-admin/approvals` → Policy) edits `authorityMatrix` + `*MinAmount` thresholds via POST `save-settings`; `?matrix=true` and `?gated-actions=true` GET params feed it.
- Purchase receipts (GRN): `purchase_receipts`/`purchase_receipt_items` + `src/lib/finance/purchase-receipts.ts`; `POST /api/finance/purchase-receipts` gates via `purchase_receipt` (inventory domain; ungated → receives immediately). Applying bumps `purchase_order_items.received_quantity` + posts `stock_movements` (productSku required) + flips PO to `partially_received`/`received`. `convertPOToBill` enforces 3-way match only when receipts exist for the PO — billable qty per line = received − already-billed (keyed on sku/description); POs without receipts keep legacy full-order billing.
- Delivery notes: `delivery_notes`/`delivery_note_items` + `src/lib/sales/delivery-notes.ts`; `POST /api/sales/delivery-notes` gates via `delivery_note` (inventory domain). SO items are JSONB — lines match by `so_line_key` (sku → description → index). Over-delivery rejected per line (ordered − delivered); apply posts stock-out `stock_movements` + flips SO to `partially_delivered`/`delivered`.
- Payment terms: `credit-control.ts` owns `payment_terms` ({days,portion} jsonb, sum=100) + `invoice_payment_schedule` (AR) — do NOT create a parallel terms table. `bill_payment_schedule` is the AP twin (`buildBillSchedule`/`getBillSchedule`/`markBillSchedulePaid`); built on every createBill (termId via `bills.payment_term_id`), walked by `markBillSchedulePaid` at all three payment-application sites (ungated create, applyPaymentToBill, approval replay).
- Landed cost: `src/lib/inventory/landed-cost.ts` owns the whole flow (value/quantity/manual allocation → moving-average unit-cost fold-in → Dr inventory / Cr payable JE). Do NOT fork it — `POST /api/inventory/landed-cost` gates via `landed_cost` (spend domain): ungated posts as before, gated returns 202 + replays create on approval. `landed_cost_vouchers.status` stays 'posted' — gating happens before creation.

- UoM on documents: `purchase_receipt_items.uom`/`delivery_note_items.uom` declare the counted UoM; apply converts via `convertUom` (chain-walking, `inventory_uom_conversions`) to the product's `stock_uom` for the stock ledger. Receipts now update `inventory_products.unit_cost` moving-average (PO UoM tracking unchanged — `received_quantity` stays in PO units). `bom_change` + `work_order_complete` are opt-in gated actions (master_data / inventory domains — gate only via band or action-scoped rule).
- Stock valuation: `src/lib/inventory/valuation.ts` — FIFO layers opt-in via `settings.inventory.valuationMethod='fifo'` (default moving_average). `inventory_stock_layers` consumed oldest-first on negative movements; `stock_movements.cogs_amount` stamps issue cost; `fifoValuation()` = on-hand value report. Movement types are a closed union (`purchase_receipt|work_order_issue|work_order_receipt|sale|transfer|adjustment|return`) — "in"/"out" are NOT valid and silently skip stock updates (fixed in purchase-receipts.ts/delivery-notes.ts).
- Reorder scan: `runReorderScan` (material-requests.ts) is invoked by the cron automation endpoint per tenant with enabled rules — auto-creates deduped MRs when stock < reorder_level.
- Document merge: `src/lib/finance/merge.ts` + `POST /api/finance/merge` {docType, sourceId, targetId}. `customer_merge`/`vendor_merge` are always-gated actions (master_data) — every FK reference rewrites on approval, source keeps history via `merged_into`, `document_merges` rows are the audit trail. Reference lists are whitelisted in merge.ts — extend CUSTOMER_REFS/VENDOR_REFS as new tables land.
- Report builder: `src/lib/reports/builder.ts` + `/api/finance/report-builder` (GET ?tables=, POST action=run/runSaved/save, DELETE). `custom_reports` saves parameterized defs over `REPORT_TABLES` — a server-side allowlist of table->columns; values always bind as params, ops whitelist (=,!=,>,<,>=,<=,like,is_null). No raw SQL reaches the DB.
- Doc-permission matrix: `doc.<docType>.<action>` keys in admin_roles.permissions (existing machinery — see permissions.ts DOC_TYPES/actions; any docType string works, DOC_TYPES is advisory). `requireDocAccess(request, docType, action, module, level)` layers on requireModuleAccess; no doc.<type> keys → module fallback (backward compatible). Wired: journals, bills, invoices, payments, payroll, pos returns, goods-receipts, POs, expenses (doc.expense_claim.create), customers (doc.customer.edit), assets (doc.asset.edit), treasury (doc.treasury_document.submit), employees (doc.employee.create/edit/delete), payroll adjustments (doc.payroll_adjustment.create).
